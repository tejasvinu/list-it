# Audit — list-it

5 November 2026, at commit `b7196ed` (the ride-unification merge). This pass looks for issues that remain after the 28–29 October audits; it does not repeat the frontend design review. Prior reports: [frontend-audit-2026-10-28.md](frontend-audit-2026-10-28.md), [audit-2026-10-29.md](audit-2026-10-29.md), [audit-2026-10-29-e2e.md](audit-2026-10-29-e2e.md).

## Status

No high-severity issue was found. The atomic PIN claim from the morning audit is correct, ownership checks are still consistent, and the build, lint, typecheck and tests are clean. The notable issues were a lockout escalation bug under concurrency, missing runtime validation on server-action arguments, and unbounded outbound request fan-out from a single pasted link.

**All findings below are fixed in this working tree, except the pagination and cold-start parts of finding 11** (the feed payload is now thinned, but old activity is still loaded in one go and `ensureIndexes`/`migrate` still run on a cold start). The final checks are recorded at the end of the document.

This pass was static plus the local checks below. It did **not** run a browser walk or mutate the configured MongoDB, so live quota, notification and cross-device behaviour is still only covered by the earlier audit notes.

## How it was checked

- Read every file in `lib/`, `app/`, `components/` and `scripts/`.
- `npm run typecheck` — clean.
- `npm run lint` — clean.
- `npm test` — 57 of 57 pass.
- `npm run build` — succeeds; 22 routes (5 static, 17 dynamic).
- `npm audit --omit=dev` — 4 high severity, all now fixable without a breaking change.
- `npm audit fix --dry-run --omit=dev` — would update `@vercel/functions` 3.10.4 → 3.10.6, `@vercel/oidc` 4.0.4 → 4.0.6, `@vercel/cli-config` 0.3.4 → 0.3.6, and remove the vulnerable nested `zod` 4.1.11.

## What's solid

- **Every page and action checks the viewer itself.** No route relies on the layout alone; anonymous visitors get the join screen or a 404.
- **Ownership and crew scoping are right.** `readRide`/`writeRide` dispatch through a validated `ride:`/`loop:` reference and always include `groupId`. Comments, stops, photos, reactions and interest rows are scoped before mutation.
- **Sessions and PINs are sound in the normal path.** httpOnly HMAC cookie, `sessionVersion` revocation on PIN reset/change/removal, scrypt with a per-rider salt, async verification, and an atomic attempt claim before comparison.
- **SSRF is tightly bounded.** Redirects are fetched only from `goo.gl`/`g.co`, every hop is host-checked, and all other input is parsed rather than fetched.
- **XSS escaping is in place.** React escapes content, Leaflet labels/tooltips are escaped, Commons URLs are restricted to `*.wikimedia.org`, and photos are re-validated with `sharp`.
- **No secrets are in git.** Only `.env.example` is tracked.
- **Security headers, error boundaries and optimistic rollback are present**, and reduced motion is handled app-wide.
- **The admin session is a random, DB-backed, revocable token**, not a derived fixed value.

## Findings

### Medium

#### 1. PIN lockouts can escalate twice in one burst of concurrent guesses

[`lockRider`](../lib/auth.ts:66) increments `lockouts` and sets `lockedUntil`. [`verifyRiderPin`](../lib/auth.ts:89) calls it from two places:

- a request that could not claim an attempt, with the filter `{ failedAttempts: { $gte: MAX_FAILS } }` (line 100);
- the request that claimed the fifth attempt, with **no filter at all** (line 110).

When six or more wrong guesses arrive together for a rider with `failedAttempts: 0`, one request sees `failedAttempts: 5`, locks them (lockout 1, 10 min), and the request that claimed the fifth slot then calls `lockRider(id, {}, now)`. That second call matches unconditionally, increments `lockouts` again and sets the next duration (lockout 2, 1 hour). A second burst after that takes the rider to 6 hours, then 24 hours. A legitimate rider with a stuck client, or an attacker who deliberately sends a burst, can therefore cause a much longer lockout than the README describes.

**Fix:** make the lock transition idempotent per run. Only one caller should move `0 → 1` or `4 → 5` and lock. For example, have the `fails >= MAX_FAILS` branch call `lockOne` with a filter that includes the exact count and no active lock, and have the no-claim branch return the existing lock instead of locking again. Then return the same message to every request in the burst.

#### 2. Server-action arguments are trusted at runtime, including the crew slug

TypeScript annotations do not validate server-action arguments. The clearest case is [`getGroupBySlug`](../lib/auth.ts:135): it runs `groups.findOne({ slug })` with whatever the client sent. `joinGroup` accepts a slug and does not require a session, so a caller able to invoke the action with `slug = { $ne: null }` (or another Mongo operator) can resolve an arbitrary group rather than the one in the URL. The same pattern exists for `signIn`'s `riderId` ([actions.ts:103](../app/g/[slug]/actions.ts:103)), and for the `commentId`/`stopId`/`photoId` lookups in the delete actions.

The impact of the slug case is gated by needing the server-action ID, which is not trivial to discover without a route bundle, but the validation boundary is missing. It also turns malformed calls into 500s instead of clean errors.

**Fix:** validate at the top of `getGroupBySlug`/`getGroupContext`:

```ts
const SLUG = /^[a-z0-9]+(?:-[a-z0-9]+)*$/;
if (typeof slug !== "string" || slug.length > 80 || !SLUG.test(slug)) notFound();
```

and require `typeof id === "string"` plus a bounded length/regex for every `_id` parameter (`riderId`, `commentId`, `stopId`, `photoId`). `rideRef` already does this for ride keys; reuse that discipline for the rest.

#### 3. A single pasted link can cause an unbounded burst of outbound requests

[`geocodeText`](../lib/geo.ts:165) splits the place text on commas and fires one Photon request per suffix at once:

```ts
...parts.map((_, i) => photon(parts.slice(i).join(", "), 1, near))
```

A 4,000-character `search` URL with hundreds of commas produces hundreds of concurrent outbound requests from one action call. [`resolveRoute`](../lib/geo.ts:479) then does the same per waypoint and has no waypoint cap; the 20-stop limit is only applied later by `validateLoop`. [`loadSuggestions`](../lib/overpass.ts:6) can hold a function for up to 40 seconds across three mirrors, and [`photosNear`](../lib/geo.ts:685) can wait 17.2 seconds (two 8-second attempts plus a 1.2-second pause). None of these actions has a per-member throttle. `joinGroup` itself has no rate limit either.

This is an availability and third-party-abuse problem: a crew member (or anyone who joins while the window is open) can burn function time, get the app's egress IP blocked by Photon/Nominatim/OSRM/Overpass, or fill the database with joins and rides.

**Fix:** cap input before fan-out — no more than 20 waypoints, no more than 6 geocode candidates, and a maximum of 80 characters of place text. Reject rather than resolve when the cap is exceeded. Add a cheap per-IP/per-rider `allow()` bucket to `joinGroup`, `previewFromLink`, `previewFromPlace`, `searchPlacesAction`, `loadSuggestions` and `fillOriginRoutes`. Consider setting a `maxDuration` for the routes that call Overpass, and lower the Overpass deadline if the plan's function limit is below 40 seconds.

#### 4. A revoked or expired session still produces a generic failure, not a recoverable state

[`requireRider`](../app/g/[slug]/actions.ts:41) throws `new Error("Sign in first")`, and the client helper [`attempt`](../components/toast.tsx:49) catches it and shows "That didn't go through. Reload and try again." The rider is not sent to the join screen, and the page stays stale. The same path is used for comments, reactions, stops, status, ride log, photo upload and profile save.

The second-pass audit says this was changed to a structured `{ ok: false, error: "signed-out" }`, but the main action file still throws. `itinerary-actions.ts` does return the structured error, which makes the inconsistency visible.

**Fix:** have `requireRider` return a result (or throw a typed sentinel), and make `attempt` detect it and `router.refresh()` to the join screen. Keep the typed text in the composer (the comment path already restores it). Add `app/g/[slug]/error.tsx` if the root boundary is not enough for the group chrome.

### Low

#### 5. Legacy loops from removed riders are still orphaned

Destinations from removed owners can be adopted by anyone (`canEdit` in [data.ts:105](../lib/data.ts:105), `ownerGone` in [actions.ts:235](../app/g/[slug]/actions.ts:235)). Legacy loops are explicitly excluded from that rule, so a loop whose owner is removed can no longer be edited, re-statused, re-photographed or deleted by anyone, and the admin page has no ride tools. This is the remaining half of the earlier "orphaned rides" finding after the unification.

**Fix:** apply the same `source === "loop" && !byId.has(riderId)` adoption rule to loops, or add admin-level ride reassignment/delete tools.

#### 6. Admin counts and "Refresh routes" ignore legacy loops

The crew admin page loads only `destinations` for the refresh button ([page.tsx:26](../app/admin/g/[id]/page.tsx:26)), and the admin index counts only destinations ([page.tsx:33](../app/admin/page.tsx:33)). [`refreshRoutes`](../app/admin/actions.ts:130) filters `destinations`, and [`scripts/reroute.mts`](../scripts/reroute.mts:12) does the same. A crew whose history is mostly loops sees an undercount and cannot refresh those routes from the UI, and the batch refresher skips them.

**Fix:** include `loops` in both counts and refresh batches. `refreshRoute` already handles an itinerary; add a loop-specific write path (or extend it to dispatch on `loop:`) and pass `loopKey(row._id)` in the batch.

#### 7. The security headers still do not constrain scripts or images

[`next.config.ts`](../next.config.ts:4) sends `frame-ancestors`, `base-uri`, `form-action` and `object-src`, but no `default-src`/`script-src`/`style-src`/`img-src`. That prevents framing and base-tag tricks, but it does not mitigate an XSS if one appears later. It also means adding a real CSP later will break the current OSM/Wikimedia image and tile sources unless they are allowed explicitly.

**Fix:** add a baseline policy, e.g. `default-src 'self'; script-src 'self' 'unsafe-inline'` (Next's inline bootstrap needs care), `img-src 'self' data: https://*.wikimedia.org https://tile.openstreetmap.org`, `style-src 'self' 'unsafe-inline'`, `connect-src 'self'`. Keep `frame-ancestors 'none'`.

#### 8. Photo storage is capped by count, not bytes, and the original bytes keep metadata

`PHOTO_CREW_LIMIT` is 400 and each upload can be 600 KB plus a 150 KB thumbnail ([validate.ts:204](../lib/validate.ts:204), [photo-actions.ts:24](../app/g/[slug]/photo-actions.ts:24)). That is about 300 MB for one crew before MongoDB overhead, against a 512 MB Atlas free tier shared by every crew. Separately, [`inspectPhoto`](../lib/photo.ts:4) only reads metadata; the original bytes are stored as-is. The client canvas strips EXIF, but a direct server-action upload can keep GPS and camera metadata.

**Fix:** add a per-crew byte quota (e.g. 150 MB) alongside the count, and re-encode the accepted image with `sharp` before storing so metadata is stripped. A byte quota also makes the 400-photo number less misleading.

#### 9. Loop activity deletes are still a collection scan

The unification stores legacy-loop activity rows with `destinationId: null` and a `loopId`. [`dropActivity`](../app/g/[slug]/actions.ts:311) therefore deletes by `{ groupId, riderId, kind, loopId }`, but `ensureIndexes` only has `activity` indexes on `{ groupId, createdAt }` and `{ destinationId, riderId, kind }` ([db.ts:202](../lib/db.ts:202)). Every loop reaction toggle and "I'm in" toggle scans the whole activity collection. This grows with every crew, not just the loop's crew.

**Fix:** add `{ groupId: 1, loopId: 1, riderId: 1, kind: 1 }` (or `{ loopId: 1, riderId: 1, kind: 1 }`) to `ensureIndexes`.

#### 10. One dev script skips the database safety guard

`reroute` and `reset` refuse a remote database unless its name ends in `-dev` ([reroute.mts:7](../scripts/reroute.mts:7), [reset.mts:10](../scripts/reset.mts:10)). `seed` is protected indirectly because it goes through `cols()` and therefore `lib/db`'s guard. [`dev-session.mts`](../scripts/dev-session.mts:7) connects with `MongoClient` directly, so it does not, and it mints a valid signed session cookie for any rider without the PIN — it only needs `SESSION_SECRET` and read access.

If `.env.local` is ever pointed at the production cluster (the earlier audit noted that dev and prod share a cluster), `dev-session` prints a working production cookie. It should follow the same rule as the other scripts.

**Fix:** have `dev-session` refuse to print a cookie when the database is not local or `-dev`.

#### 11. Feed, profile and activity payloads still grow without bound

The crew page was fixed to use `getRiderCounts`, but [`/g/[slug]/r/[riderId]`](../app/g/[slug]/r/[riderId]/page.tsx:15) still calls `getFeed(ctx)` and filters on the client, [`/g/[slug]/activity`](../app/g/[slug]/activity/page.tsx:16) loads up to 1,000 activity rows **and** the full feed, and `getFeed` sends every route point for every ride. `ensureIndexes` and the "done" `migrate` scan also run on every cold start ([db.ts:177](../lib/db.ts:177)).

Nothing is slow with the current demo data, but one member can add unlimited rides, stops and comments, and every page load then carries all of it.

**Fix:** add pagination or a projection to the feed/profile/activity paths, stop sending `route` where only a thumbnail is needed, cap rides/stops/comments per crew, and remove the one-time `migrate` after production has run it.

#### 12. Date handling still has a midnight edge, and the profile month uses the host timezone

`FeedView` captures `Date.now()` during render ([feed-view.tsx:63](../components/feed-view.tsx:63)) and `RideLog` does the same ([ride-log.tsx:16](../components/ride-log.tsx:16)). The server and the browser therefore compute "today" at different instants; the earlier IST fix means this now only disagrees when a request crosses IST midnight, but it is not eliminated. `ProfilePage` formats the join month without `timeZone` ([profile-view.tsx:78](../components/profile-view.tsx:78)), so a rider joining near the end of a month can see a different month from the server.

**Fix:** pass a server-computed `today`/`now` as a prop (or compute it after mount) and use `timeZone: "Asia/Kolkata"` for the join date.

#### 13. The photo lightbox does not trap focus

`Sheet` now moves focus in, traps Tab and restores it, but the photo dialog in [`rider-photos.tsx:146`](../components/rider-photos.tsx:146) only moves focus to the close button and handles Escape/arrow keys. Tab can move into the page behind the dialog, and the background is not inert.

**Fix:** reuse the focus-trap effect from `Sheet`, or extract it into a shared hook.

#### 14. Share links depend on forwarded headers

[`siteOrigin`](../lib/origin.ts:5) builds the admin share URL from `x-forwarded-host`/`host` and `x-forwarded-proto`. On Vercel these are set, but behind another proxy or a local tunnel a wrong `Host` produces a wrong (or attacker-chosen) share link. The calendar route has the same pattern via `new URL(request.url).origin`.

**Fix:** prefer an explicit `APP_ORIGIN`/`VERCEL_PROJECT_PRODUCTION_URL` when set, and fall back to the forwarded headers only in development.

#### 15. Dependency advisories are now fixable without a breaking change

`npm audit` reports four high-severity issues from `zod` through `@vercel/functions` → `@vercel/oidc` → `@vercel/cli-config`. The dry run shows a safe, non-forced update. The vulnerable code is still not reachable from user input, so this is not urgent, but the earlier "wait for upstream" advice no longer applies.

**Fix:** run `npm audit fix --omit=dev` (or `npm install @vercel/functions@^3.10.6`) and commit the lockfile. Re-run the build and tests afterwards.

### Smaller notes

- `app/error.tsx` and `app/global-error.tsx` use `retry`, which is correct for Next 16.4 (verified in `node_modules/next/dist/docs`).
- `npm run build` loads `.env.production.local` on this machine. Keep that file out of the working tree or ensure every build-time route stays free of database access.
- The `allow()` fixed-window counter uses an upsert; concurrent first requests for a brand-new key can, in principle, produce a duplicate-key error rather than a 429. A small retry around the upsert would harden it.
- `rid()` maps bytes into a 56-character alphabet with modulo bias. The entropy loss is negligible at 10–12 characters, but rejection sampling would remove the bias.
- There is no CI workflow (`.github` is absent); lint, typecheck, tests and build are manual. Add a GitHub Action running those four commands on push/PR.
- There are no tests for `lib/auth.ts` (including the lockout transition), server-action authorization, notifications or the calendar route. The 57 tests are good coverage for pure parsing/routing/validation, not for the concurrency bug above.

## Fixes applied

- **1:** `lockRider` now carries the full-count/no-active-lock filter on every call, and both branches use one `lockResult()` helper. A burst can only escalate once.
- **2:** Added `isValidId`/`isValidGroupSlug` in `lib/validate.ts`; `getGroupBySlug` refuses invalid slugs, and `signIn`, `deleteComment`, `deleteStop`, `deletePhoto` and the admin actions validate their IDs.
- **3:** `geocodeText` caps at 5 candidates and 240 characters; `resolveRoute` caps at 22 points; join, previews, searches, photo refresh, stop suggestions, origin routes, itinerary edits, photo uploads, comments and stops have `allow()` buckets.
- **4:** `requireRider` and the loop/itinerary contexts now `redirect()` to the join screen when the session is gone.
- **5:** Destination and legacy-loop adoption now uses the same rule (`canEdit`, `ownDestination`, stop/photo deletion).
- **6:** Admin counts and refresh batches include `lib.loops`; `refreshLoop` updates the loop collection and its stop-suggestion cache; `scripts/reroute.mts` processes both sources.
- **7:** CSP now has `default-src`, `script-src`, `style-src`, `img-src`, `font-src`, `connect-src`, `manifest-src` and `worker-src`; dev gets the extra eval/websocket allowances. `poweredByHeader` is off.
- **8:** `PHOTO_CREW_BYTES_LIMIT` (200 MB) is enforced, and `sharp` re-encodes both images so EXIF/GPS and orientation metadata do not survive.
- **9:** Added the loop activity index.
- **10:** `dev-session` refuses a non-local, non-`-dev` database before minting a cookie.
- **11 (partial):** `getFeed` thins route geometry (160 points) and itinerary leg routes; detail pages still receive the full route.
- **12:** `requestNow()` supplies one server timestamp to `FeedView`, `ActivityView` and `JoinScreen`; the profile join month uses `Asia/Kolkata`.
- **13:** The photo lightbox now traps Tab and restores focus.
- **14:** `siteOrigin` prefers `APP_ORIGIN`/Vercel URLs; the calendar route uses it too.
- **15:** `npm audit fix --omit=dev` updated the Vercel chain; `npm audit --omit=dev` now reports 0.
