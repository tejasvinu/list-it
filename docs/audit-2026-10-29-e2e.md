## Findings

### High

#### 1. Stop names are rendered as HTML on the ride map (verified)

[maps.tsx:99](../components/maps.tsx:99) passes `s.name` to Leaflet's `bindTooltip`. Leaflet sets the tooltip's `innerHTML`, as [DivOverlay.js:280](../node_modules/leaflet/src/layer/DivOverlay.js:280) shows. I added a stop named `<b class="audit-x">Audit stop</b>` and hovered its marker. The tooltip contained a real `<b>` element.

Any crew member can add a stop, and so can anyone who joins with the link while joining is open. A name with an event-handler attribute would run script in the browser of every rider who hovers or taps that stop. The script could then post comments, delete that rider's own rides or rename them. It can't read the session cookie, which is httpOnly.

A stop's name can also come from a pasted Maps link or from Photon when the name field is left empty, and those names go through the same code.

**Fix:** pass escaped text, e.g. `bindTooltip(escapeHtml(s.name))` (the helper is already in that file), or a DOM node with `textContent`. Destination pins already escape their labels. A `script-src` CSP would limit the damage of anything similar later.

#### 2. A failed action either fails silently or replaces the whole page (verified)

No route has an `error.tsx`, and the client never catches a rejected server action. When I revoked the session on an open ride page:

- **"Count me in"** flipped on, then quietly flipped back. The console showed `Uncaught Error: Sign in first`. Reactions go through the same code ([social.tsx:19](../components/social.tsx:19) and [social.tsx:138](../components/social.tsx:138)).
- **Sending a comment** replaced the ride page with Next's default "This page couldn't load", and the typed comment was lost. Actions that use `useTransition` all take this path: comments, stops, status, "I've ridden this", delete, find photos and profile save.

The same happens on a dropped connection, which is common on rides, and after any PIN reset or PIN change on another phone. When an action throws in [destination-form.tsx](../components/destination-form.tsx) `run()` or `movePin()`, the spinner never stops.

**Fix:** have `requireRider` failures come back as `{ ok: false, error: "signed-out" }`, and handle that by refreshing to the join screen. Wrap action calls in `try/catch`, show a toast and restore what the user typed. Add `app/g/[slug]/error.tsx` and `app/global-error.tsx` with a Reload button.

### Medium

#### 3. The road mix counts long highway stretches as "City" (verified against OSRM)

[`roadSplitOf`](../lib/geo.ts:445) puts each routing step in a bucket based on where the step starts. The first highway step out of Bengaluru usually starts inside the 22 km city radius, so its whole length counts as city.

| Ride | App's "City" | Distance actually inside 22 km | Step at fault |
|---|---|---|---|
| Kotagiri | 153 km | about 51 km | 110 km on NH275 |
| Nandi Hills | 60 km | 48 km | 19 km on NH44 |

The error also flows into [`mainRoad`](../lib/format.ts) (the milestone cap colour) and `splitSummary`.

**Fix:** measure each step's own geometry against the radius. Request `geometries=geojson` per step, or split each step's distance by the share of its points inside the radius. Rides that are already saved keep their old split until someone refreshes or re-saves them.

#### 4. The PIN lockout still allows a steady guessing rate (from code)

The lock is a fixed 10 minutes after 5 misses ([auth.ts:9](../lib/auth.ts:9)), so a single rider can take roughly 700 guesses a day. That covers the 10,000 PINs within about two weeks. Across a whole roster the first success comes much sooner. The per-IP limit helps less than it seems, because addresses are cheap to rotate.

**Fix:** make repeat lockouts escalate (for example 10 min, then 1 h, then 24 h), or cap misses per rider per day. Show lockouts on the admin page, which already shows "locked out".

#### 5. Change PIN has no confirm step (from code)

[profile-view.tsx:251](../components/profile-view.tsx:251) asks for the current PIN and then the new one once. Joining asks twice. A typo leaves the rider signed in on this phone only. They then can't sign in anywhere else, and they can't change the PIN again, because they don't know the "current" one. Only the admin can recover them.

**Fix:** add the same "Once more" step that joining uses.

#### 6. Activity day headings use the server's timezone (from code, not reproduced)

`dayLabel` in [activity-view.tsx:57](../components/activity-view.tsx:57) uses local `Date` methods. On Vercel (UTC), activity from 00:00–05:30 IST is grouped under a different day than in the browser. That causes a hydration mismatch, and the headings can disagree. The local dev server runs in IST, so I couldn't reproduce this locally.

**Fix:** compute the date in `Asia/Kolkata`, the way `todayYmd` does.

### Low

7. **Sheets leave focus behind them (verified).** After a sheet opens, focus stays on the button that opened it, even though the sheet sets `aria-modal="true"`. Move focus into the sheet, keep it there while open, and return it on close ([sheet.tsx](../components/sheet.tsx)).
8. **The PIN pad shows no sign of working (verified).** Signing in and joining took about 5 s locally with four filled dots and no indicator. `PinPad` has a `busy` prop, but nothing passes it.
9. **A plus code gives a ride called "Dropped pin" (verified),** even when the town follows the code. Use the first part of the locality as the name.
10. **Adding a stop with coordinates took 6–10 s.** `resolvePlace` reverse-geocodes even when the rider typed a name.
11. **Distances run lower than the landing page's own samples.** OSRM routes Yercaud via the Hosur–Adiyamankottai road and unnamed hill roads for the last 26 km. That gives 363 km round trip, while the landing page sample says 462 km. Riders will compare these numbers with Google Maps.
12. **Commons still drops photo lookups.** Seeding hit a timeout and "too busy" on 2 of 5 rides (morning finding 14).
13. **A removed rider's name blocks new joins with that name.** [actions.ts:57](../app/g/[slug]/actions.ts:57) also matches removed riders, and the error tells the person to use "I'm already in", where that name isn't listed.
14. **`npm run reset -- --force` would drop any database,** including production's `list-it`. Refuse names that don't end in `-dev`, as `lib/db.ts` already does.
15. **Anyone can keep the admin from signing in.** The global admin limit is 50 tries an hour from everywhere put together ([auth.ts:146](../lib/auth.ts:146)). Existing admin sessions last 30 days, so the impact is small.
